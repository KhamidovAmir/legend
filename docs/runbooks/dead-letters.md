# Runbook: DeadLettersAppeared

**Что значит:** потребитель не смог обработать сообщение после всех ретраев (или сообщение невалидно) и переложил
его в `<topic>.dlt`. Партиция не заблокирована, остальные сообщения идут.

**Влияние:** конкретное сообщение не применено. Для команды это означает зависшее исключение.

**Проверить**

1. Какой топик: метка `topic` у `kafka_dead_letter_total`.
2. Прочитать сообщение из `<topic>.dlt`; заголовки `kafka_dlt-exception-message`, `kafka_dlt-original-offset`
   говорят, что и где упало.
3. По заголовку `correlationId` найти цепочку в логах.

**Действия**

| Причина | Действие |
|---|---|
| Невалидное сообщение (нет заголовков, битый JSON) | выяснить продюсера; это нарушение контракта |
| Временная ошибка, пережившая ретраи (БД была недоступна) | после восстановления переложить сообщение из DLT в исходный топик — обработка идемпотентна |
| Ошибка в коде потребителя | исправить, выкатить, затем переложить |
| Результат внешней системы без нашей операции (`external.delivery.results`) | чужой или опередивший результат; сверить по `idempotencyKey` |

Автоматического перекладывания из DLT в репозитории нет — это ручная операция.
